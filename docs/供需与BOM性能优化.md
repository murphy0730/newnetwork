# 供需与BOM性能优化

本次仅优化执行方式，计算口径继续以[供需计算口径与场景示例](供需计算口径与场景示例.md)为准。没有更换语言，也没有重建业务数据库。

## 改动

- 按拓扑顺序建立整数编码、部门索引及连续边数组。跨产业传播不再在每条边上查询编码Map，也不反复读取部门、父子关系。
- 每个口径、月份先读取一遍净需求与记录存在标记，避免按每个产业重复查询。
- 预测供应、指令供应共享同月同口径的需求矩阵；供应量与最终缺口仍分别计算。
- 净预测缓存命中时直接返回，不再创建编码、月份的JSON键。
- 每次跨产业计算复用中间数值数组，按产业清零。原有传播顺序、有限数值检查、已知/未知来源标记保持不变。

跨产业传播仍为O(产业数×(编码数＋有效边数))，并未改变来源选择算法。原始BOM及外部接口格式保持兼容；整数图索引只在需要计算的引擎中创建，在线产物装载继续直接读取预计算结果。

## 同机基准

测试日期：2026-10-23。Node.js v24.19.0，Intel Core i7-12700H。合成数据为8层BOM、6个月，同时包含预测及未完工指令供应模式。每组独立运行3次，取中位数。优化前后使用同一脚本、数据及机器，串行执行；性能会受系统负载、JIT和GC影响。

| 数据 | 指标 | 优化前 | 优化后 | 加速比 |
|---|---|---:|---:|---:|
| 8,000编码、21,000有效边、21部门，预测有缺失 | 三口径需求预计算 | 940.4 ms | 100.5 ms | 9.4倍 |
| 同上 | 其中跨产业预计算 | 828.3 ms | 28.7 ms | 28.9倍 |
| 同上 | 完整离线产物构建 | 1,181.9 ms | 329.8 ms | 3.6倍 |
| 30,000编码、131,250有效边、13部门 | 三口径需求预计算 | 3,417.9 ms | 300.8 ms | 11.4倍 |
| 同上 | 其中跨产业预计算 | 2,873.6 ms | 53.7 ms | 53.5倍 |
| 同上 | 完整离线产物构建 | 4,650.0 ms | 1,293.1 ms | 3.6倍 |

“三口径需求预计算”包含所有月份、三种口径及两种供应模式；完整离线构建额外包含模板范围处理、拓扑、索引、数据分块、矩阵压缩与SQLite产物写入。均不包含Excel解析、业务库发布、网络传输或页面绘制。这些结果不代表无法导入本机的真实数据表现。

汇总查询没有同等幅度的提升：8千编码的首次汇总查询约30.2→33.7 ms，3万编码约87.8→76.7 ms；本次主要收益在构建与重新计算。混合基准进程的RSS高水位约487→559 MiB，包含两组数据生成及多轮查询、构建，本次不宣称降低峰值内存。新增常驻图索引约为每条有效边12字节、每编码9字节，需求矩阵在两种供应模式间共享。

## 正确性与复现

- 两组数据的全部需求矩阵及末端100编码、6个月的来源结果，优化前后SHA-256校验和完全一致。
- S1～S38场景结果表无需改变，自动验算仍与文档完全一致。
- 新增5组固定随机种子的BOM核验，以独立来源上溯结果逐项核对数值与完整性标记；另测供应模式共享和场景部门隔离。
- 全量168项自动测试、44项界面回归，以及逐月来源、动态系数和Excel导出浏览器检查全部通过。
