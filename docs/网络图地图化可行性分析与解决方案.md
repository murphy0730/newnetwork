# 供应网络图「地图化」改造 —— 可行性分析与解决方案报告

> 版本：v1.0（2026-09-15）
> 范围：`forecast-graph.js`（前端渲染）+ `server/service.js`（图谱接口，仅 T2 涉及）
> 性质：**分析 + 方案，不改业务算法与数据口径**
> 结论一句话：**可行。已有架构（G6 v5.1.1 + 服务端全量图 + 自研分层布局 + 凸包分组）距离
> "地图体验"只差一层"LOD 显示调度"，且地基（世界坐标系、分组抽象）已经存在。**

---

## 1. 问题定义

### 1.1 现状问题

1. **大图卡死**：编码多时前端渲染卡顿甚至无响应，交互（点击、拖拽、缩放）不可用。
2. **缩放无层级**：缩小只是"变小"，不是"聚合"，信息糊成一团，没有详略自适应。
3. **无法横向浏览**：想"像地图一样左右滑动看别的部门/产业"做不到，因为当前视图是
   "一屏一张图"，没有可滑动的连续平面。
4. **维度不通用**：地图化需求不应只服务于"按部门"，而要覆盖现有全部维度组合。

### 1.2 目标

| 目标 | 一句话描述 |
| --- | --- |
| 地图式缩放 | 放大看编码细节，缩小看聚合全貌，信息详略随缩放自适应 |
| 空间浏览 | 无筛选时看全部，可平移连续浏览同颗粒度下的其他组织单元 |
| 多维正交 | 布局 / 口径 / 聚类 / 染色四类维度任意组合下都能地图化 |
| 数字正确 | 任何缩放下，汇总数字与明细一致，不产生"两套真相" |

### 2.2 卡顿根因：图元占比

G6 v5.1.1 为 Canvas 渲染，每个节点 = 1 圆 + 1 文本标签，每条边 = 1 线 + 1 箭头（`endArrow`）。
精确图元账（12 万节点 / 59.4 万边）：

| 图元 | 数量 | 占比 | 代码位置 |
| --- | ---: | ---: | --- |
| 节点圆 | 120,000 | 8.4% | `forecast-graph.js:122` |
| 节点标签 | 120,000 | 8.4% | `forecast-graph.js:129` |
| 边线 | 594,000 | 41.6% | `forecast-graph.js:142` |
| 边箭头 | 594,000 | 41.6% | `forecast-graph.js:143` |
| **合计** | **≈1,428,000** | 100% | |

**关键结论：边与箭头占 83%，标签仅 8.4%。** 优化优先级必须按图元占比排，而不是按"标签最显眼"。

### 2.3 四个全量卡点

| # | 位置 | 问题 | 触发时机 |
| --- | --- | --- | --- |
| 1 | `:412-415` | `_applyStates()` 构造 71.4 万个状态 key 并全量 `setElementState` | **每次点击节点** |
| 2 | `:143` | 59.4 万个边箭头全量渲染 | 常驻 |
| 3 | `:466-467` | `restyle()` 全量 `updateNodeData` / `updateEdgeData` | 切染色、切路径高亮 |
| 4 | `:263` / `:294` | 凸包每帧清空重建 SVG，逐成员两次坐标 API 往返 | 聚类开启时拖拽 / 缩放 |

### 2.4 三条已确认的代码事实（避免重复踩坑）

1. **`select()`（`:477`）是死代码**，全库无调用点。点击路径是
   `node:click`（`:181-197`）→ `chainCode = id` → `_applyStates()`。
   → **不要优化 `select()`，收益为 0。** 真凶是 `_applyStates` 的全量状态刷新。
2. **`_usePreset()`（`:362`）= `layoutMode === 'layered' || nodes.length > 800`**。
   → 节点 > 800 时 `preset` 恒为 `true`，`combo-combined` 分支（`:447`）不可达（不会"布局数秒"）；
   → 但因此**"力导向"按钮在 >800 节点时完全失效**（假开关），需一并修复。
3. **世界坐标系 = "一屏"**。`_presetPos()`（`:364-371`）把布局宽高绑定到容器尺寸，
   `layered()` 内部（`:12-17`）二分求 `columns` 使长宽比匹配视口，`render()` 再 `fitView()`（`:454`）。
   → **左右没有可滑动空间，与性能无关。**

## 3. 可行性论证

### 3.1 支点一：世界坐标系已存在

`layered()`（`:7-41`）已经把**全量节点坐标一次性算好并缓存在 `_presetMap`**（`:364-371`），
且该纯函数在 10 万节点上验证过位置计算（`docs/多选筛选与完整BOM分层说明.md:39`）。
**缺的不是坐标系，而是"按视口和缩放级别选择要渲染的子集"。** 这是改造量大幅缩小的根本原因。

### 3.2 支点二：分组抽象已存在

`_clusterKey()`（`:238-243`）与 `_clusterKeys()`（`:246-253`）已实现
制造部门 / 产品大类 / 加工地三维分组，且处理了"一个编码属于多个加工地组"的情况。
**聚合层不需要新写分组逻辑，只需在现有抽象上加一层"投影"。**

### 3.4 支点四：聚合层对象极少，空间浏览无需视口裁剪

- L0（部门 × BOM 层）：约 20 部门 × 10 层 ≈ **200 块**
- L1（大类 / 加工地 × BOM 层）：约 50~300 组 × 10 层 ≈ **500~3000 块**

几百到一千个图元，G6 全量渲染毫无压力，**可以自由平移**。这正是地图的规律：
缩小的时候数据天然就少，所以能自由浏览；放大到细节才开始按视口加载。
聚合块**前端就能算**（`/api/graph` 返回的 nodes 已带 `make_dept` / `level` / `risks` /
`single` / `siteCount` 等字段），按 `(组织维度, level)` 分组计数是毫秒级。

## 4. 解决方案

### 4.1 总体架构：新增一层 LOD 调度器

```text
后端 /api/graph ──► setData(nodes, edges)           （不改）
                        │
                        ▼
              世界坐标系（layered() 已有，只算一次）
                        │
                        ▼
            ┌───────────────────────────┐
            │  LOD 调度器（唯一新增层）      │
            │  · 读 scale  → 定层级          │
            │  · 读视口    → 算可见集         │
            │  · 读主轴    → 定横向分带        │
            │  · 产出：渲染集 + 聚合集（纯函数） │
            └───────────────────────────┘
                        │
              ┌─────────┴──────────┐
              ▼                    ▼
     addNodeData/removeNodeData   凸包 overlay
     （增量，不调 setData）         （只画可见成员）
```

**设计原则**：调度器是**纯函数**（输入：全量数据 + 世界坐标 + 视口 + scale + 主轴；
输出：渲染集）。纯函数意味着可单测、可回放、可离线验证——这是"计数守恒"可证的前提。

### 4.2 不变式（硬约束，任何一条被破坏即方案失败）

1. **坐标系不变**：缩放、平移、切层级、切维度，不得改变节点世界坐标。
2. **口径不变**：`mode` / `source` / `version` / `month` / `span` 语义与现状完全一致。
3. **计数守恒**：聚合块数字 = 成员真实计数，且与后端 `Query.summarize` 同源。
4. **数量不可加**：缺口、供应、需求绝对值跨编码禁止相加
   （`docs/前端改善建议与洞察接入任务书.md` §6）。
5. **双向一致**：图上任何数字 = 汇总表 = 洞察面板在同一 `trace` 下的数字。

### 4.3 四档位 LOD 定义

| 层级 | scale 区间 | 画什么 | 对象预算 | 标签策略 |
| --- | --- | --- | ---: | --- |
| L0 战略层 | ≤ 0.25 | 加工地 × BOM 层聚合块 + 关键路径骨架常显 | ≤ 400 | 聚合标签（组名 · N 编码 · M 高风险） |
| L1 聚合层 | 0.25 – 0.6 | 聚合超节点 + 聚合超边 | ≤ 1500 | 仅超节点标签 |
| L2 网络层 | 0.6 – 1.2 | 真实节点，仅高风险 / 关键路径 / 选中带标签 | ≤ 1200 | 选择性标签 |
| L3 编码层 | > 1.2 | 全标签 + ×配比 + 加工地角标，视口外剔除 | ≤ 800 | 全标签 + 碰撞剔除 |

**临界迟滞**：进入阈值与退出阈值错开（如 L1→L2 在 0.6 进入、0.52 退出），防边界抖动。
**切换去抖**：`aftertransform` 后 120ms 无新事件才切换；缩放过程中不切换层级。

### 4.4 空间浏览：二维地图（横轴 = 组织维度，纵轴 = BOM 层）

| 轴 | 含义 | 现状 |
| --- | --- | --- |
| 纵轴 | BOM 层（最多 10 层） | ✅ 已实现（`layered()` 按 `level` 分带） |
| 横轴 | 组织维度：部门 / 大类 / 加工地 | ❌ 未实现（`group` 仅用于同层内排序 `:26`） |

改造四要点：

1. **横轴分带**：把 `group`（`_clusterKey()` 结果）从"排序键"提升为"空间带"，
   每带一个固定水平区间，带内按 BOM 层纵向排。
2. **坐标系与视口解耦**：`layered()` 的 width/height 不再等于容器尺寸，
   改由数据量决定（`列数 × 带宽`）。容器只决定视口。
3. **首次 fitView，之后不再自动 fitView**；视口由用户控制（`drag-canvas` / `zoom-canvas` 已注册）。
4. **ResizeObserver（`:172-180`）改为保持视口中心**，不再触发 120ms 后全量重排。

**语义必须区分**：

| 动作 | 语义 | 是否重排 |
| --- | --- | --- |
| 平移 / 缩放 | 在**同一批数据**内浏览 | ❌ 不重排 |
| 筛选 / 切版本 | **换一批数据** | ✅ 允许重排 |

现在两者走同一条 `setData → render → fitView` 路径，平移能力被筛选路径吃掉了，必须拆开。

### 4.5 多维正交：覆盖 96 种组合

先按"是否决定坐标"给维度分两类：

| 维度 | 决定坐标？ | 切换时的行为 |
| --- | --- | --- |
| 布局（力导向 / 分层） | ✅ | 允许重排 |
| **空间主轴（新增）** | ✅ | 允许重排 |
| 口径（直接父子 / 跨产业 / 最顶层） | ❌ | 只改连边，不动坐标 |
| 染色（层级 / 风险 / 加工地 / 无） | ❌ | 只改颜色，不动坐标 |

**新增"空间主轴"选择器**（默认 = 当前聚类维度），把"聚类"的双重职责拆开：

| 选择器 | 职责 |
| --- | --- |
| 聚类（已有） | 画哪些凸包 |
| 空间主轴（新增） | 横向按什么分带 |

**两种布局统一到"带"抽象**：

| 布局 | 分带方式 | 依据 |
| --- | --- | --- |
| 分层 | **硬分带**：坐标精确对齐带中心，y = BOM 层 | 自研 `layered()` |
| 力导向 | **软分带**：`forceXPosition` = 带中心，`forceXStrength` 调强度 | bundle 实测 `getXForceOptions` / `setupXForce` |

主轴 × 布局 = 8 格，共用一套分带代码（分带逻辑只依赖"分组键 → 带序号"映射）。
产品定位：**力导向 = 探索模式，分层 + 主轴 = 地图模式。**

### 4.6 聚合层的正确性（业务红线）

| 显示项 | 可聚合？ | 说明 |
| --- | --- | --- |
| 编码数 / 匹配数 | ✅ | 成员计数 |
| 风险编码数 | ✅ | 布尔或运算 |
| 当月单一加工地编码数 | ✅ | 计数 |
| 数据不完整编码数 | ✅ | 计数 |
| 组间连接对数量 | ✅ | 用于聚合边线宽 |
| 缺口 / 供应 / 需求绝对值 | ❌ | **量纲不统一，禁止相加** |
| 缺口分配到某上层 | ❌ | 违反口径 |

数量类信息改用**个数、最大值、占比、分布直方图**表达，绝不显示"缺口合计"。

### 4.7 关键路径跨层连续

聚合边 `critical = 任一成员边 critical`（或运算），线宽 ∝ 组间关键路径连接对数。
→ L0/L1 呈现为连续高亮走廊，L2/L3 放大后落回具体编码。

### 4.8 现有功能兼容矩阵

| 现有功能 | 地图化后行为 |
| --- | --- |
| 视图切换 网络图 / 汇总表 | 不变 |
| 布局 力导向 / 分层 | 分层 = 硬分带，力导向 = 软分带；修假开关 |
| 口径三种 mode | 只改连边，不动坐标 |
| 聚类 无 / 部门 / 大类 / 加工地 | 保留；职责收敛为"画哪些凸包" |
| **空间主轴（新增）** | 横向分带依据，默认 = 聚类维度 |
| 染色 层级 / 风险 / 加工地 / 无 | 只改颜色，不动坐标；处理与聚类重复的"加工地" |
| 展开深度 1/2/3/5/10 | 不变（数据范围仍由后端 depth 控制） |
| 单击锁定链路 + 洞察 | 保持；状态改增量 |
| 双击下钻 | 保持；聚合块上双击 = 展开（`collapseCombo`/`expandCombo`） |
| 关键路径 / 风险路径 | 保持；低层级呈现为走廊 |
| 缩放 滚轮 / ＋ / － / ⤢ | 保持；新增层级指示器 |
| 边透明度 / 配比标签 / 隐藏孤立点 | 保持；配比标签仅 L3 |
| 凸包边框与分组标签 | 保持；只画可见成员但计数为总数 |
| BOM 分区分层标签 | 保持 |
| 显示全部节点 | 语义调整为"适配到全图（L0）" |
| 节点洞察 / 汇总表 / 导出 | 完全不变（数字同源） |

## 5. 分阶段实施路线

> 成本为**单人前端工作量估算**，不含测试与联调，供决策参考，非承诺工期。

| 阶段 | 内容 | 成本 | 依赖 | 收益 |
| --- | --- | ---: | --- | --- |
| **T0 止血** | ① `_applyStates` 增量状态 → ② 边与箭头按层级降级 → ③ 注册 `optimize-viewport-transform` + `auto-adapt-label` → ④ 凸包批量取坐标 | 1–2 天 | 无 | 143 万 → 数千图元，点选流畅 |
| **T0.5 空间浏览** | 横轴分带 + 坐标系解耦 + 空间主轴选择器 + 力导向软分带 + 视口策略 | 2–3 天 | T0 | 可左右滑动浏览，多维组合 |
| **T1 语义缩放** | LOD 调度器 + 视口裁剪（`getCanvasByViewport` + 增量增删）+ 层级指示器 | 2–4 天 | T0.5 | 地图手感完整，加工地主轴可用 |

**推荐顺序**：T0 → T0.5 → T1 → T2。
T0 与 T0.5 纯前端、低风险、可独立验收；T1 是"地图"与"普通图"的分界线；T2 解决传输量上限。

| 图元数 | 各层级 `getNodeData().length + getEdgeData().length` |

### 6.3 正确性验收（不可妥协）

1. **计数守恒**：任一聚合块的编码数 / 风险数 / 单一加工地数 / 不完整数，
   与后端 `Query.summarize` 在同一 `trace` 下完全一致。
2. **双向一致**：图上数字 = 汇总表数字 = 洞察面板数字。
3. **无跨编码相加**：全链路检索确认不存在对缺口 / 供应 / 需求求和后展示的字段。
4. **坐标不变性**：缩放、平移、切染色、切口径后，任一节点世界坐标不变。

## 7. 风险登记册

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 聚合块被误读为"已分配供应" | 高（业务） | 聚合块常驻说明；与凸包语义统一声明 |
| 聚合计数与汇总表不同源 → 两套真相 | 高（业务） | 聚合计数复用 `Query.summarize`；纳入 6.3 验收 |
| 跨层切换视觉跳变 | 中 | 迟滞区间 + 保持鼠标下方世界坐标不动 |
| 增量增删导致元素状态残留 | 中 | `addNodeData` 后立即 `setElementState` 补齐 |
| 力导向坐标不稳定（随机性） | 中 | 固定随机种子 + 收敛后锁定坐标为 preset |
| 多加工地编码无法落单一带 | 中 | 主带分配 + 角标/连线表达其他归属，UI 明确说明 |
| G6 升级覆盖手工补丁 | 中 | 升级时检查上游是否修复 `push.apply`，保留万节点回归 |
| `enableCulling` 非一等 option | 低 | 作为可选优化，不纳入 T1 关键路径 |
| 对象预算假设失效 | 中 | 调度器内硬约束，宁可少画不可超预算 |

---

## 8. 结论与建议

1. **可行**：四个支点（世界坐标系、分组抽象、G6 能力、聚合层对象少）均已实证存在，
   改造集中在"新增一层 LOD 调度器"，不重写布局、不碰后端、不改口径。
2. **先做 T0 + T0.5**：纯前端、单文件为主、2–5 天内可见滑动手感，是风险收益比最高的起点。
3. **三条红线不可破**：坐标系不变、计数守恒、数量不可加。其中"数量不可加"是最容易被
   忽略的业务事故源，必须写进验收。
4. **诚实边界**：WebGL 不在当前 bundle；加工地主轴（300 带）需 T1 视口裁剪；12 万节点
   秒开需 T2 后端聚合。这些都已在方案中按依赖排序，不承诺超出技术边界的"无限流畅"。
