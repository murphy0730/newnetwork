# BOM项目模板范围与异常规则

项目模板仅取表3 BOM的`parent_template`（父项模板）、`child_template`（子项模板）。不使用表4库存的项目模板，也不要求编码在预测表或制造属性表中有记录。

按编码汇总全表全部父项、子项位置的模板，统一判断后建立有效BOM。规则不依赖输入顺序，也适用于多个文件合并导入。

| 同编码的模板信息 | 处理 |
|---|---|
| 所有记录一致为`AI` | 参与BOM关系计算 |
| 所有记录一致且明确为非`AI`，如`POC` | 该编码相关边不参与BOM关系计算 |
| 任一位置模板缺失 | 输出模板缺失提示，保留编码参与 |
| 同编码出现不同模板，包括父项/子项不一致或空值与非空值混用 | 输出模板不一致提示，保留编码参与 |

一条关系只有父项、子项都保留时才进入有效BOM。不跨越非AI编码连接其上下游。明确非AI的另一端仍会使该关系不参与；模板冲突例外只保留发生冲突的编码。

网络图、直接父子/跨产业/最顶层查找、供需传播、汇总表和离线产物使用同一有效BOM。其他表仍保留原有范围规则；非AI编码若在其他表中有记录，可能作为独立编码展示，但不恢复被排除的BOM关系。

例如：

```text
02233VXE(POC) → 02302155(AI) → 02315NVE(AI) → 03028VPE(AI)
```

排除`02233VXE → 02302155`后，`02302155`成为有效BOM的根。若`02315NVE`与`03028VPE`同产业且`02302155`归为未知部门，跨产业来源为`02302155`；最顶层来源也为`02302155`。它没有预测记录时需求显示未知，不补成显式0。

模板异常写入导入任务的BOM问题清单，保留文件、工作表、原始行号、编码及对应模板字段。级别为提示，不阻止导入。原始BOM仍存入产物，数据表行数为原始有效记录数，网络关系数为参与计算的边数，因此两者可能不同。

升级后旧产物需要重新构建和装载，才能按新规则生成拓扑及预计算结果；可从已有数据重建，无需重新提供全部原始文件。仅刷新浏览器不会更新已构建的关系。
