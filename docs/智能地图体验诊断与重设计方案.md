### 根因链（forecast-graph.map.js）

**根因 1：换档阈值和"字能看清"完全脱钩 —— 这是"一放大就跳档"的直接原因。**
- `ZIN = 1.55`（行 266）：相对**本档 fit 缩放**放大 1.55 倍即换档。
- B 档世界尺寸约 2631×765（placeColumns 输出），fit ≈ 0.38。所以用户放大到绝对 zoom ≈ **0.59** 就被踢进 C 档；而 12px 的标签要 zoom ≈ **1.0 以上**才可读。
- 结论：**标签可读所需的 zoom 区间，被换档阈值整段跳过了**。用户永远处在"字刚要清楚"的瞬间被换档。site 聚类（58 列，世界更宽）时 fit 更小，情况更糟。

**根因 2：三档三个世界坐标系 + 每档 fitView 硬切换 —— 这是"闪一下"和"不像地图"的直接原因。**
- 行 794-796 注释明说："三档坐标系互不相同：A 打包 / B 柱列 / C 层行，绝对 zoom 不可比，故每档进入时都用 fitView"。
- 换档执行链（行 796-816）：`setData → render → fitView` 全部同步硬切，无过渡、视口跳变。地图的"丝滑"来自**统一世界坐标 + 渐进细节**，我们现在是三张独立小图互相替换。
- 每档 fitView 把内容居中塞进视口 → 视觉上永远是"聚在屏幕中间的一小坨"，没有地图的延展感。

**根因 3：块的信息密度太低，风险"写了但看不见"。**
- `_blockLabel`（行 440-443）：单行文本 `块名 · 数量`（colorBy=risk 时追加 `· 风险N`），12px，无换行、无强调。
- A 档默认染色是 `hashColor(块名)`（行 432）——**颜色是哈希随机分配的，和业务无关**；风险数只有切到"风险染色"才体现为块底色，且低/中/高三档色的区分度弱（#8fb0a8/#cfc08a/#cf9a90 面积大时才可辨）。
- 一行字放不下还会溢出/挤压（B 档子块最小 58px 宽，"热处理产业 · 12"必然截断）。

**根因 4：B 档是"全体展开"而不是"聚焦展开"。**
- `_buildLevelB`（行 489-543）把**所有** 12 个块全部展开成 96 个子块，点击的焦点块只是描边变黄（行 524）。用户点了一个块，期待的是"这个块占满视野、其他块退后"，实际得到的是"全部打乱重来"。这是"不像地图"的第二层：地图点进一个国家，是国家占满屏幕，邻国缩小在四周。

**根因 5：C 档自动聚焦"编码最多的块"（钣金产业 85），但业务上最有价值的往往是风险块。**
- 行 561-563：`focusKey = count 最大的块`。1004 编码里 494 个总量不足，但聚焦选择完全不看风险。

## 二、业务场景：这张图到底在什么时刻、被谁、用来做什么决策

把三档重新翻译成业务动作，而不是技术名词：

### 场景 1｜管理层 3 秒扫视（A 档 = 指挥仪表）
> "494 个总量不足，堆在哪些产业？会不会往总装传导？"

- 他不需要编码、不需要层结构。他要的是：**哪几个块发红、红到什么程度、风险往哪个方向流**。
- 现状差距：块色是哈希随机的；风险数藏在标签文本里；汇总流只按"边条数"算粗细，不按风险权重。
- **要求：A 档自带风险仪表**——风险徽标 + 风险占比条 + 高风险块自动置顶/放大 + 风险流加权。默认视图不切换任何控件就能回答场景 1。

### 场景 2｜计划员定位风险堆积层（B 档 = 结构放大镜）
> "电机产业风险高，是成品层堆积还是第 4、5 层原材料的问题？"

- 点电机产业块 → 期待：**这个块展开占视野中央，7 层子块纵向排开，风险层一眼可见**；其他块退到边缘灰化。哪层风险占比高，就点哪层进 C。
- 现状差距：12 个块全部展开互相挤压；字全糊；焦点块无视觉优先。

### 场景 3｜采购员/跟单员查编码（C 档 = 执行清单）
> "第 5 层这 11 个有缺口的编码，哪些是单一加工地？缺口传导到哪个上层？"

- 进入时按风险排序、缺口编码带标签、点击看链路。现状 C 档基本达标（标签、行标签、链路高亮都有），但进入路径太绕（滚轮赌灵敏度）且焦点块选择不看风险。

### 场景 4｜异常推演回看（推演后地图联动）
> 推演一个"某加工地停工"后，回到总览想看影响扩散：停工地所在的块应该变成红色高亮，受影响的下游块变橙。
- 这是"块=仪表"的自然延伸，现有 A 档完全没有承接推演结果的钩子（推演页和地图页割裂）。

**业务优先级结论**：场景 1（默认 A 档风险仪表）价值最高、成本最低——它决定这张图"打开第一眼有没有用"；场景 2（聚焦展开）第二；换档丝滑度是贯穿性体验底座。

## 三、重设计方案：让它在行为上"像地图"，而不只是叫地图

四条设计原则，按依赖顺序：

### 原则 1（核心底座）：统一世界坐标系——换档不换世界
- A 档 `placeBlocks` 算出的块坐标作为**永久锚点**。B 档子块不再全局重排，而是**从锚点纵向展开**（锚点上方留出列标题，子块在锚点附近纵向堆叠，块间距拉开）。C 档编码从子块锚点展开成行。
- 三档共用一个世界。初始 fitView 一次；此后**换档不再 fitView**，只做两件事：① 切换可见元素集合；② 视口中心不动。
- 效果：滚轮放大时块在原地"长大、裂开"，缩小时"合拢、退远"——空间记忆连续，闪烁自然消失。这是地图"丝滑"的本质：**不是有动画，而是坐标系从来没动过**。
- B 档配合"聚焦式"：点中的块展开占视野中央约 60%，其他块折叠成小色块钉在原地（灰色、只留名字），提示"这里还有别的簇，点它切焦点"。

### 原则 2：标注永远是屏幕像素尺寸（screen-space 标签）
- 地图铁律：**当前级别该显示的名字，在任何缩放下都 ≥ 11px**。
- 实现：记录每档 fit 基准 `_fitZoom`，在 `aftertransform`（已有钩子，行 367）里按 `实际字号 = 12 / zoom` 反向补偿，用 `updateNodeData + draw()` 节流更新（100ms 一次，只更新可见标签）。G6 v5 的 label 是矢量文本，放大不糊、缩小补偿后不糊。
- 配套：标签超宽自动省略（块名 6 字内全显，超出 `…`），完整名放 hover tooltip。

### 原则 3：换档阈值重新校准 + "看不清才换档"反向逻辑
- 换档逻辑从"放大 N 倍就换"改成**跟随标签密度**：当前档的标注已经全可读、且出现大量空白时才允许升档（即 ZIN 1.55 → 1.9，HYST 0.18 → 0.3，实测滚轮 4 格变成 7~8 格）。
- 降档（缩小）保持现有灵敏度——缩小看全貌是低频合法操作，快速降档无害。
- 换档瞬间做 300ms 的透明度交叉过渡（旧档元素 fade-out / 新档 fade-in），消除最后一丝硬切感。

### 原则 4：块 = 业务仪表（信息卡化）
A 档块重新设计为三行信息卡（自定义绘制，矩形块本来就 260×187，空间够）：

```
┌───────────────────────────┐
│ 电机产业            ⚠ 23   │  ← 标题行 + 风险徽标（红底白字数字）
│ ██████████░░░░  84 编码   │  ← 风险占比条（风险编码 / 总编码）+ 总数
│ 缺口23 · 单一9 · 不完整4  │  ← 风险结构行（灰底小字，hover 展开明细）
└───────────────────────────┘
```

- **默认就有风险徽标 + 占比条**，不再依赖"切风险染色"；"染色"下拉保留，但变成可选的分析视角而非唯一的风险入口。
- 汇总流加权：流的粗细从"跨块边条数"改为 `max(边条数, 风险边数×2)`，风险流保持暖色——管理层顺着红色流就能看到"风险往总装传导"。
- 聚焦选择改为**风险加权**：C 档自动聚焦 `风险数` 最多的块，而不是编码数最多的块。

### 各原则成本与依赖

| 优先级 | 改造 | 依赖 | 预估工作量 | 解决的吐槽 |
|---|---|---|---|---|
| P0 | 统一世界坐标 + 去 fitView（原则 1，含 B 档聚焦式展开） | placeColumns/placeLevelC 重写为"锚点推导" | 3~4 天 | 闪一下 / 聚中间 / 不像地图 |
| P0 | screen-space 标签（原则 2） | aftertransform 节流更新 | 1~1.5 天 | 字小 / 放大就跳档（配合原则 3 才完整） |
| P0 | 阈值校准 + 交叉过渡（原则 3） | — | 1 天 | 一放大就跳档 / 硬切 |
| P1 | 块信息卡 + 风险流加权 + 风险优先聚焦（原则 4） | 自定义节点绘制 | 2~3 天 | 信息量少 / 风险不凸显 |
| P1 | bug 修复 B1~B5 | — | 合计 ~半天 | 面包屑残留等 |
| P2 | 推演结果联动地图（场景 4） | 原则 4 的徽标体系 | 2 天 | 推演与总览割裂 |

**总计：P0 约 5~6.5 天，P0+P1 约 8~10 天。** 建议一个迭代内先做 P0 全部（体验底座），P1 的信息卡紧跟（业务价值最大单项）。

### 三角色自检
- **业务**：默认打开就能回答"风险在哪、往哪流"——满足；三档动词化为"扫视→定位→查编码"，与实际工作流对齐。
- **领导**：报表/表格已满意不动；地图改造是纯前端单文件（forecast-graph.map.js）+ 少量 forecast-app.js 联动，不动数据层、不动服务端，风险可控。
- **数据科学**：布局算法（螺旋打包、松弛收敛）是确定性纯函数，锚点推导只改坐标系映射不改算法骨架，可单测（现有 tests/map-graph.test.js 同口径扩展）。

## 四、待确认的三个设计决策

1. **B 档聚焦式展开**（点谁展开谁，其余折叠）——是否接受"其他块折叠成小色块"的信息损失？备选：保持全体展开但焦点块占 60% 视野、其余等比缩小。
2. **风险徽标默认常显**——默认视图叠加风险维度后，"类型染色"（模板哈希色）退居第二视角，是否接受？
3. **升档阈值放宽到 1.9**——滚轮变"钝"换取阅读时间，是否接受？（可做成设置项"换档灵敏度：快/标准/稳"）
