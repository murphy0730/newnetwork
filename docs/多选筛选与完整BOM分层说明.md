# 多选筛选与完整 BOM 分层

本次实现以本文为准，替代旧文档中“图谱最多 1000 节点 / 5000 条边”的描述。

## 使用方式

- 加工地：展开选择框，可按代码或名称查找并勾选多个加工地，然后点击“应用筛选”。
- 编码 / 名称：输入关键词，在候选中勾选多个编码，已选编码显示为可移除标签；点击“加载更多候选”继续查找。未勾选编码时，仍支持直接按关键词过滤。
- 同一维度的多选取并集，不同维度取交集。筛选只改变展示，不缩减计算下层总需求时纳入的上层计划。
- 维度筛选保留匹配编码的一跳 BOM 上下游作为上下文，计数明确区分匹配数与展示数。风险过滤仍只显示符合风险条件的编码。
- “聚焦编码”是单编码下钻入口，与多编码筛选分开；下钻深度仍定义所选网络范围。

## 完整图与布局

`/api/graph` 不再通过 `limit` 截取节点，也不再截取关系边。所选深度、筛选条件与关系口径仍然生效。列表分页及搜索候选分页不影响图谱完整性。

默认采用分层视图。位置使用完整 BOM 拓扑中的最长路径层级：根节点为第一层，每个下层至少位于其全部父项的下一层。同一编码即使在不同链路上深度不同，也只保留一个节点。产品大类、制造部门、加工地以及分析口径均不重新定义 BOM 层级。

每层拥有独立区域，按节点数安排多行，使用交错位置和父项位置排序。列数依据画布宽高比计算，展开或收起侧栏、调整窗口尺寸时重新适配。深层不再合并到固定末层。节点现有配色保持不变。

聚类排序限制在同一层内，凸包边框也分层绘制；多加工地编码仍能出现在多个加工地分组中。800 个节点以上使用确定性 BOM 定位，避免力导向迭代拖慢大图，页面会显示此说明；这个阈值不减少任何节点或边。完整大图仍需通过缩放、平移、筛选与下钻查看单个编码。

## 接口兼容

- `site`：单值兼容；多值可用 JSON 数组，如 `site=["S001","S002"]`，在 URL 中须编码。
- `codes`：精确编码多选，如 `codes=["A","B"]`。AI 工具参数可直接传字符串数组。
- `search`：兼容原来的模糊关键词。与 `codes` 同时传入时取二者并集，再与其他维度取交集。
- 图节点新增 `matched`，响应新增 `matchedNodes`；`truncated` 恒为 `false`。
- 修复产品大类未参与缓存键和仅按大类筛选被忽略的问题。

## 性能与维护

布局计算函数与图组件共同放在 `forecast-graph.js` 中，并导出供 Node 测试使用；`forecast-layout.js` 仅保留 Node 兼容入口。页面无需额外加载布局脚本，避免旧服务进程未注册新静态路径时出现 `Cannot read properties of undefined (reading 'layered')`。不改变预测算法或已有构建产物。

节点查找和链路遍历改用索引；染色、透明度和配比标签更新只重新绘制样式，不重复布局。

本地 `vendor/g6.min.js` 做了一处精确修复：绘图变更监听器原先用 `mutationRecords.push.apply(..., records)` 追加所有变更，万节点网络可超过浏览器调用参数栈上限，表现为计数正常、画布空白及 `RangeError: Maximum call stack size exceeded`。现改为循环追加，顺序与内容不变。升级 G6 时应检查上游是否修复，并保留万节点浏览器回归。

验证包含：1400 节点 / 6000 边完全返回、多选交并集和需求不变、大类缓存隔离、10 万节点 / 10 层位置计算、父项始终位于下层之前，以及原有洞察和推演测试。浏览器大图能力受机器内存与绘图开销影响；10 万节点的位置计算通过不等于已验证 10 万节点浏览器交互速度。

2026-09-11 验证结果：`node --test tests/*.test.js` 的 41 项测试全部通过；`node tests/ui-browser.js` 在 1 万编码、19416 条当前口径关系边上完成 27 项交互检查，浏览器异常列表为空。覆盖多选、KPI 筛选、BOM 分区、聚类后父子顺序、凸包缩放、洞察、推演准备及文件夹导入。截图保存于 `test-output/network-layered.png`。

启用时需重启后端，并用 `Ctrl+F5` 刷新页面，使图接口、新布局脚本及图形库补丁同时生效。无须重导数据或重建预测矩阵。
