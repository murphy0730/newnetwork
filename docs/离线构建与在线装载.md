# 离线构建与在线装载

本次将全量解析、校验、BOM 建图、周期路径与数值预计算移入独立构建进程。HTTP 服务负责流式接收文件、启动任务、报告进度和装载完成后的版本切换。既可以在网页操作，也可以在另一台机器离线构建后上传产物。业务计算口径、聚类接口和独立推演保持兼容。

## 网页使用

重启服务后打开“数据管理”。

1. 下载 Excel 模板，或查看“表格式与填写要求”。填写预测、BOM、制造属性和产业映射；库存、调整、生产指令按需补充。预测的加工地用于供应集中分析，制造周期均值和 CV 用于链路分析。
2. 同一预测版本的所有分片文件一起上传，确认工作表类型和表头行，点击“校验并预览”。CSV 流式落盘，构建在独立进程进行。页面任务区显示阶段、进度、错误和取消按钮，关闭页面不取消构建。
3. 构建完成后确认编码规模和告警，点击“装载并切换版本”。装载期间原版本继续查询；新版本装载成功才发布。
4. 也可以直接上传 `.supply` 离线产物，校验后装载。当前产物可完整下载；大表可按表下载 CSV。

构建/校验失败会释放本批上传暂存；修正后可立即重新上传，包括相同文件名。字段错误带文件、工作表、逻辑行号和字段名，页面可下载错误清单。未提交的上传与构建预览有效期 24 小时，任务记录保留 7 天；过期清理由后续请求或服务启动触发。重启后已完成任务与预览可继续使用，运行中的任务会明确标为“中断”，不会悄悄重算或发布。

预测按本批涉及的完整计划日期版本替换，库存按完整日期快照替换；其余表按整表替换。不能把同一版本的多个分片分成多次提交，否则后一次会覆盖该版本前一次的数据。独立销售、采购已在外部预处理时继续使用默认净预测口径，避免重复调整。

## 命令行构建

使用 Node.js 24，无需安装额外依赖。在项目根目录运行：

```powershell
npm run build:data -- --config docs/build.example.json --out build-output/dataset.supply
```

先将 [配置示例](build.example.json) 中的文件路径替换为真实输入。输入路径相对配置文件目录；`--out` 相对当前命令目录，未传 `--out` 时使用配置中的 `output`。输出文件已存在会拒绝覆盖，建议每次使用新名称。命令逐行输出 JSON 进度；失败以非零退出码结束。

Excel 可自动识别工作表：

```json
{
  "files": [{ "path": "业务数据.xlsx" }],
  "output": "2026-09.supply"
}
```

也可明确指定工作表和表头，`headerRow` 从 0 开始：

```json
{
  "files": [{ "path": "业务数据.xlsx", "selections": [
    { "sheet": "月度产出", "table": "forecast", "headerRow": 0 },
    { "sheet": "产品结构", "table": "bom", "headerRow": 1 }
  ] }],
  "output": "2026-09.supply"
}
```

追加新预测版本时，在配置中指定既有产物作为基线，其余未替换的表/日期会保留：

```json
{
  "base": { "artifact": "previous.supply" },
  "files": [{ "path": "new-version.csv", "table": "forecast" }],
  "output": "next.supply"
}
```

本地目录库也可作为基线：`"base":{"dbPath":"../data/control-tower.sqlite","revision":1}`。省略修订号时取构建开始时的当前版本。CLI 仅产出文件，不会替换在线数据；将产物上传并确认装载后才生效。

## 旧数据与算法升级

启动服务只恢复产物里的图索引、周期路径和预计算矩阵，不做全量重算。检测到旧版单块快照，或产物算法指纹与当前代码不一致时，元数据返回 `needsBuild=true` 和明确提示，原文件保留；数据管理、模板和任务接口仍可使用。点击“重建当前数据”，或使用以下配置离线迁移：

```json
{
  "operation": "rebuild",
  "base": { "dbPath": "../data/control-tower.sqlite" },
  "output": "../build-output/migrated.supply"
}
```

新旧数据版本及推演历史均保留。旧库历史占用不会因迁移自动缩小，避免误删回溯数据。备份请包含目录库及其 `.builds` 目录；复制正在使用的 SQLite 库需使用一致性备份或先停止服务。单个 `.supply` 文件包含完整业务表和所有版本的矩阵，适合离线传输。

## 存储与计算实现

| 模块 | 职责 |
| --- | --- |
| `server/import-stream.js` | CSV 流式解码、分批规范化、Excel 工作表转换、浅层合并 |
| `server/build.js` | 独立构建进程及 CLI，合并/校验/建图/预计算 |
| `server/artifact.js` | 不可变分块产物、清单、校验和、图与矩阵恢复 |
| `server/build-jobs.js` | 磁盘暂存、持久任务、串行构建队列、失败清理和取消 |
| `server/store.js` | 版本目录、产物引用、审计和情景请求 |
| `server/main.js` | HTTP 控制、后台读线程装载、原子版本切换 |

`.supply` 是独立 SQLite 文件，包含清单、压缩表块、图块和压缩 Float64 矩阵。表块通常不超过 2000 行或 2MiB；单个特长字段可能超过目标块大小。整个数据集不会被 `JSON.stringify` 成一个字符串，也不再同时写快照和逐行明细两份数据。目录库发布只写很小的产物引用及审计事务。

清单记录格式版本、算法指纹、构建 ID、时间、各表行数、编码数、边数、层数、预测版本、月份、加工地、告警和输入哈希。数值按明确的小端序编码，表块与矩阵分别校验 SHA-256。上传产物在独立进程校验，之后在候选读线程中装载；任何一步失败都保留现有在线版本。并发提交使用修订号比较，过期产物返回 409。

所有预测版本、全部月份、三种关系口径和 forecast/mo 两种来源在构建时完成预计算。基线缺矩阵直接报错要求重建，不会退回在线补算。在线仍需执行筛选、排序、有界图查询和结果组装；这些不是全量建图或基线预计算。推演复用基线图和未变化月份矩阵，只重新计算受影响月份；跨出原预测窗口的延期由独立情景引擎处理。

## 接口

原查询、聚类和 `/api/scenarios` 接口保持兼容。业务与模型调用同一服务端口径。

| 接口 | 用途 |
| --- | --- |
| `POST /api/import/file?name=...` | 原始 CSV/Excel 二进制流上传、异步识别 |
| `POST /api/import/preview` | 基于上传文件或结构化批次启动独立构建 |
| `POST /api/import/artifact?name=...supply&baseRevision=...` | 流式上传并校验已构建产物 |
| `POST /api/import/commit` | 按 `previewId` 装载并发布 |
| `POST /api/builds/rebuild` | 按 `baseRevision` 显式重建并发布 |
| `GET /api/builds` / `GET /api/jobs/{id}` | 当前身份的持久任务列表/进度/错误 |
| `POST /api/jobs/{id}/cancel` | 取消未进入原子发布阶段的任务 |
| `POST /api/import/discard` | 释放尚未被构建使用的上传，正文 `{"ids":[...]}` |
| `GET /api/import/schema` | 表字段、格式约定、模板地址 |
| `GET /api/export?kind=template` | 下载 Excel 模板 |
| `GET /api/export?kind=artifact` | 流式下载完整产物 |
| `GET /api/export?kind=csv&table=forecast` | 按表流式导出标准列 CSV |

异步接口返回 202 和 `jobId/poll`。任务最终为 `completed` 或 `failed`；失败包含 `error.message/details`。取消、文件过期或基线变更后须重新上传/构建。任务记录与产物构建 ID 可用于追溯；AI 工具不接受任意 SQL、脚本或文件路径。

## 容量边界与实测

新流式/离线路径移除了固定总文件大小、累计单元格、编码数、BOM 边数的拒绝阈值。仍保留单 CSV 字段 16Mi 字符保护、64MiB 结构化 JSON 请求限制，以及既有业务校验（例如月份窗口与无环 BOM）。大型数据请使用文件流而非 JSON 请求。Excel 本身有工作表容量限制，当前解析库在独立进程内展开整个工作簿，超大输入优先使用分片 CSV。

这并不意味着物理容量无限：完整规范化数据、邻接图、索引仍需内存；原版本和候选版本装载重叠、历史预测版本、推演及多人查询也会增加内存。构建进程默认堆上限 8192MiB（`BUILD_HEAP_MB`），服务工作线程默认 6144MiB（`SERVICE_HEAP_MB`），两者不是全机内存配额。大数据生产部署需根据真实明细量和并发量配置资源；不能只按编码数估算。

2026-09-10 在本机 Node v24.19.0、i7-12700H、约 16GB 内存实测：12 万编码、10 层、300 加工地、59.4 万 BOM 边、132 万预测行、11 个月。预测 CSV 为 671,748,120 字节，1716 万单元格；规范化表累计约 10.85 亿 JSON 字符，超过旧版约 5.37 亿字符单字符串上限。

| 真实 HTTP 操作 | 一次测量 |
| --- | ---: |
| 四份文件流式上传及识别 | 4.75 秒 |
| 独立解析、校验、建图、写入与预计算 | 31.22 秒 |
| 候选装载与原子切换 | 8.74 秒 |
| 单编码 11 个月详情 | 78 毫秒 |
| 首次 12 万编码分析分页 | 821 毫秒 |
| 构建/装载期间健康接口最大响应（90 次） | 16.62 毫秒 |

本次最大表块约 1.52MB，产物约 31.87MB；测试备注大量重复，压缩率不能代表真实业务文件。目录主库此时 4KiB，另有 WAL/共享内存文件，不能将 4KiB 理解为全部持久化占用。本次在线基线初始为空，结果不代表满规模双版本装载峰值、并发推演性能或 Excel 同等规模性能，也不承诺任意机器相同耗时。

首次同规模测试发现旧式逐字符 CSV 拼接导致 V8 字符串链内存膨胀，现已改为片段拼接；修复后完成上述测试。失败隔离与错误反馈也经过实际内存不足场景验证。

## 验证命令

```powershell
npm test
npm run test:import-browser
npm run benchmark:artifact
```

规模测试会生成约 687MB 原始 CSV、暂存及产物，使用独立测试库，不操作业务数据。可用 `SCALE_CODES` 调整规模，默认 120000。结果文件：`test-output/artifact-benchmark.json`、`test-output/build-browser.json`。回归覆盖三种口径、矩阵恢复无需重算、历史版本、CSV 跨块引号、Excel 与分片 CLI、失败重试清理、取消、任务重启恢复、过期提交拒绝、产物校验、角色鉴权及独立推演。

本轮最终验证：30 项后端回归通过；浏览器导入流程 6 项检查通过；现有图形交互 18 项检查通过，包含产业/加工地聚类、风险筛选与下钻。浏览器结果无未捕获脚本异常。测试脚本现已从 Git 忽略规则中放行，生成的数据、浏览器目录及构建产物仍保持忽略。
