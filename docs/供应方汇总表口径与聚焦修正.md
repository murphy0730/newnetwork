# 本轮范围

本轮针对「供应网络总览 → 视图 → 汇总表」，供应方角色可用，汇总表的需求方角色暂时停用。网络图和节点洞察继续使用原来的分析规则。汇总表聚焦时收起原节点洞察，避免同时展示不同跨产业规则下的数值。

## 原问题

- 前端仅在需求方角色传递聚焦编码；后端供应方列表也未应用精确聚焦。
- 三种口径下的关联编码和表头固定使用“跨产业编码”，且仅露出前三个来源。
- 无父项时，缺口返回空值；多月库存后缺口还可能产生负数，未表达“不适用”。
- 汇总表发送 `linked=1`，排除了独立编码。
- 原跨产业算法遇到首个不同 `make_dept` 即停止，与本轮示例 C 应取 A、B2 不一致。

## 本轮计算定义

按用户示例 `A(a) → B1(a) → C(c)`、`B2(a) → C(c)` 实现。示例后文“B2 和 C”按上下文理解为“A 和 B2”。

| 口径 | 需求来源 | C 的来源 |
| --- | --- | --- |
| 直接父子 | 直接父项 | B1、B2 |
| 跨产业 | 先沿供应编码所在产业向上追溯，进入上一个产业后，继续沿该产业内部 BOM 到其顶端 | A、B2 |
| 最顶层 | 沿全部 BOM 追溯到无父项的根节点 | A、B2 |

产业只按表6 `make_dept` 区分。跨产业的“顶端”指没有同产业父项的编码；进入上层产业后，不继续越过该产业到更高产业。同一编码有同产业及异产业父项时，进入该产业后的追溯仅沿同产业父项展开。若后续明确要取“首个跨产业编码”，应调整汇总表关系策略，而不能只替换表头。

每条路径的用量为各条 BOM 配比之积；同一来源多条路径汇合时，累计用量相加。来源净需求 × 累计用量得到来源贡献。中间编码自身预测不与上游折算需求叠加。

例如 A=100、B1=80、B2=20、C=650，配比 A→B1=2、B1→C=3、B2→C=5：

- 直接父子：240+100=340，C 预测缺口为 -310。
- 跨产业和最顶层：600+100=700，C 预测缺口为 50。
- 若起始库存30，库存后缺口20；连续6个月同计划，累计缺口300，库存后缺口270。库存只计起始月一次。

无对应口径需求来源时，来源编码、需求显示“—”，供应与库存正常展示，两种缺口固定为0。缺失必要预测或产业数据仍标记不完整，不能用0替代未知需求。有来源时，缺口保留正负值：正值不足，负值富余。

## 展示、筛选和导出

- 未聚焦且无其他维度筛选时展示全部编码，包括顶层及独立编码。
- 排序在后端分页前统一执行：没有BOM下层的底层编码优先，再按距底层的最长路径逐层向上；同层先排有当前口径需求来源的编码，再排当前月份有预测记录的编码，最后按编码稳定排序。独立编码同属底层，但无需求来源，因此排在同层有来源的编码之后。显式0预测属于有数据；多月显示按起始月判断预测记录是否存在。页面、筛选结果与导出使用同一顺序。
- 聚焦编码精确筛选供应编码，不把其需求来源误当成供应编码列；其他维度筛选仍可叠加，但不会裁剪需求贡献。
- 每页20个供应编码，来源逐行展示，同编码供应量、总需求及缺口合并单元格。分页总数按供应编码计，不按展开后的来源行计。
- 表头随口径变为父项编码、跨产业编码、最顶层编码；每个来源展示产业、累计用量、各月折算需求。
- 支持“单独月份”和“累计月份”，均可从当前选中月份向后选择1～6个月，默认单独月份、1个月。单独月份仅在所选起始月展示两版结果：预测缺口=需求−净供应（不含库存）、库存后缺口=预测缺口−起始月库存；后续月份均不计库存，也不结转前月余额，只展示各自的预测供需缺口，页面和Excel不再生成后续月份的库存及库存后缺口列。若从10月开始，10月就是本次分析的首月。累计月份仍只显示一组期间结果，供需数量相加，库存只计起始月一次。9月起选3个月时，表头分别为9月/10月/11月，或一组“2026年9-11月”；跨年范围显示两端年份。KPI和风险筛选仍按起始月，并在界面提示。
- 月份按连续自然月取值；版本内部断月或超过已维护范围时，保留对应月份，预测及相关缺口显示未知。首月库存缺失时，不含库存缺口正常计算，含库存结果显示未知；后续月份的计算不依赖库存。累计结果不完整时不用0补齐。
- Excel导出逐来源展开，总供应、总需求、总缺口只记在编码的首行，避免对导出表求和时重复统计；请求固定到页面显示的数据版本。
- 汇总表切入时切为供应方，明确提示需求方暂未开放；网络图角色功能保留。

## 接口与实现

`GET /api/analysis?summary=1&role=supply&code=C&mode=cross&month=2026-09&span=6&limit=20`

`summary=1`启用汇总表规则；与`role=demand`组合返回400。`trace.view=supply-summary`、`trace.relationRule=industry-block-root-v1`标记结果规则。每个供应编码返回完整`targets`，含`code`、`make_dept`、`coeff`、期间`demand`及逐月`monthly`。来源行不携带分配缺口；所有缺口属于供应编码整体。

参数`periodMode=individual|cumulative`选择月份计算方式，默认`individual`。响应顶层`periods`给出表头范围，各供应编码的`periods`给出所选方式下的完整结果；累计方式长度为1，单独方式长度为`span`。页面和Excel导出均消费`periods`。为兼容旧调用，编码行顶层供需/缺口数值仍保留期间合计；AI或新增调用方应读取`periods`，不要将兼容合计字段当作单独月份结果。

`periods[].inventoryIncluded`说明是否启用库存对比：单独月份依次为`true,false,...`，累计月份为`true`。单独月份的非首月`inventory`和`coverageGap`返回`null`表示不适用，以`gap`作为不含库存的计算结果，不能将`null`误读成0库存或库存数据缺失。

新增计算模块`server/supply-summary.js`。汇总按拓扑顺序计算，数值传播O(V+E)，排序O(V log V)。只为当前页展开来源关系，避免建立全编码两两关联矩阵。查询进程缓存两个月份/口径/供给来源上下文，版本和情景按独立Engine隔离。首次访问新的汇总口径会在查询进程中计算和缓存；未更改离线产物格式，也无需重导数据。此边界与原来预计算产物中的跨产业规则不同，不能把两者结果混用。

## 验证

新增回归覆盖精确聚焦、独立编码、三口径来源与合计、多路径汇合、未知数据、6个月库存、情景隔离、原始量预处理和指令供应。浏览器检查覆盖按来源分行、角色关闭、表头切换、聚焦、6个月展示、Excel数值及既有图交互。测试数据库独立于业务数据库。

修改后使用`end.cmd`停止旧服务、`start.cmd`启动，再在浏览器`Ctrl+F5`刷新。无需重新导入数据。
