# 后端计算、导入与推演说明

本文说明业务计算口径。最新导入架构、操作步骤、CLI 配置与 12 万编码实测见 [离线构建与在线装载](离线构建与在线装载.md)。本轮以后台构建、产物装载为主，前端仅补充数据管理页的任务控制与提示；网络图和聚类实现保持原样。

## 启动与验证

使用 Node.js 24，运行 `node server/main.js`，或双击已有的 `start.cmd`，访问 http://127.0.0.1:8787 。不需要安装图数据库或 npm 依赖。修改后端后需要重启服务；启动时自动加载已提交快照及预计算结果。默认数据库为 `data/control-tower.sqlite`。

```powershell
node --test tests/*.test.js
node --max-old-space-size=1536 tests/service-benchmark.js
node tests/import-benchmark.js
```

测试使用独立临时数据库，不改业务数据库。规模测试生成数据及结果在 `test-output/`，不属于业务导入数据。

## 业务计算口径

每个编码的月度预测是当月可产出量。供应方用自己的净预测对照所有相关上层的合计需求；需求方查看相关下层在全局范围内是否不足。缺口为 **需求 − 供应**，正数表示不足。库存覆盖缺口在此基础上再扣除所选月初库存；不会用库存掩盖预测本身不匹配的问题。

| 分析方式 | 需求来源 |
| --- | --- |
| direct | 所有直接父项的净使用预测 × 对应 BOM 用量，再合计 |
| cross | 沿上层穿过已配置为本产业的编码，在首个非本产业编码或本产业最顶层停止，折算并合计 |
| top | 追溯所有最顶层编码，按累计 BOM 系数折算并合计 |

同一上层沿多条有效 BOM 路径到达同一下层，路径系数相加。中间编码自己的预测不再与传入需求相加后继续展开，避免重复需求。界面搜索、加工地、产业筛选只改变展示范围，不缩小参与需求合计的竞争上层范围。需求方详情的 `contribution` 是参考折算量，不是已分配供应或缺口。

`cross` 中的本产业通过制造部门映射明确配置，并非自动按每个下层所属产业动态切换。缺制造属性、缺预测、产业映射不明确会标为不完整；明确的零预测与缺少记录不同。没有父项的终端编码不标成“供应过剩”。

当前默认 `input_mode=net`：预测已经在外部预处理采购、独立销售等因素，表2只维护、不再次参与调整。只有切换为 `raw` 时，表2“供应”增加该编码供给，“使用”减少该编码向下折算的需求；剔除超过原预测会阻止提交。

库存仅使用分析月份一号的快照，排除子库类型以 `生产-三品`、`备件-` 开头的记录。该日期完全没有快照则库存未知；同日快照中未列出的编码视为零。累计分析只使用起始月库存一次，缺月不能跳过去当连续可用计划。

加工地按代码识别，只有名称时临时按名称识别。只统计正数量产出；缺加工地数量单独显示，不能推断为独家供应。月度单一加工地、整个预测期间单一加工地、最大份额与加工地缺失分别返回。它们表示计划中的供应集中情况，不代表已经核实所有可替代加工能力。

关键路径在真实 BOM 上按加工周期均值累计，取最长路径；周期变异系数用于揭示波动，不直接换算成未经校准的延误概率。任一依赖分支周期缺失，关键路径会标记不完整。风险路径包含所有有风险的分支，不只最长分支。

`source=mo` 时，用未完工、未取消指令的计划产出替换供应量，需求侧仍由预测与 BOM 形成，禁止将预测和指令重复加为供应。当前仍是月粒度分析；逐日生产排序、订单分配、日级库存及停线日期属于后续扩展。

## 后端结构与预计算

| 模块 | 职责 |
| --- | --- |
| `server/main.js` / `worker.js` | HTTP、角色鉴权、候选读线程装载、独立推演 |
| `server/import-stream.js` / `importer.js` | 流式 CSV、分批规范化、Excel 识别及模板 |
| `server/build.js` / `build-jobs.js` | 独立构建、CLI、持久任务、暂存清理 |
| `server/artifact.js` | 分块产物、清单、校验和、图与矩阵恢复 |
| `server/engine.js` | 后端专用数值矩阵计算、按编码读取、路径与累计查询 |
| `server/service.js` | 业务接口、快照、推演覆盖层、缓存与导入流程 |
| `server/store.js` | 产物引用、版本目录、情景与审计 |
| `server/openapi.js` | OpenAPI说明与模型工具定义 |

新版本存储采用不可变分块 SQLite 产物及轻量 WAL 版本目录，不再同时写整份 JSON 快照和逐行明细。计算采用内存有向无环图、父子邻接表和拓扑序。聚合需求使用拓扑动态规划，不生成任意两编码之间的全路径表，避免多分支网络组合爆炸。当前无需先引入图数据库；后续可为复杂图检索增加图数据库投影，保持业务 API 不变。

构建在独立进程完成全部预测版本、月份、三种口径和两种供应来源。确认提交时先装载候选产物，成功后原子发布引用。启动只恢复结果；遇到旧快照或算法指纹变化明确要求重新构建，不会自动重算。

历史预测版本也在构建时预计算。任意筛选组合、所有编码对之间的关系、任意推演组合不会在导入时全部展开。月度聚合采用 `O(月份 × 口径 × 来源 × (编码数 + BOM边数))` 计算。矩阵每个编码存两个64位数：已知需求量和完整标记；3万编码、11个月、3种口径、一个供应来源约15.1MiB数值数据，不含图与原始明细。

编码详情、跨月曲线和报告热力图按需读取目标编码的矩阵格子，只补充这些编码的加工地、库存及风险字段。分页总览需要扫描当月编码用于统计和排序，最多缓存两个完整月份/口径结果。图谱最多返回1000节点、12000边；聚类所需产业、加工地、层级字段保留，前端聚类逻辑不变。

## 推演与一致性

推演请求按基线修订号、预测版本固定输入。支持单编码或指定加工地的 `set`、`add`、`percent`，以及质量损失、延期、加工地停工。未指定加工地时按原数量比例分摊；原量全零时在既有零记录间均分。无法凭空新增没有预测记录的编码月份，应先维护明确的零计划。

批量修改最多1000项。后端一次建立“版本/编码/月”的行索引，只替换命中的行；同一编码月先整体修改、再按加工地修改时，按请求先后顺序执行。相同编码/月/加工地的重复项会拒绝。

情景复用基线图及未变化月份的矩阵，受影响月份按拓扑重算。当前增量粒度为“月份”，不是仅重新计算单个受影响节点集合。对比先读精简数值，只对实际改变的编码生成详细风险字段，降低对象创建和内存占用。重开已保存推演也复用基线矩阵，连续推演优先保留基线缓存。

月度预测没有具体每日排产信息，因此延期按当月每天均匀产出估算跨月移动；指令延期按已有计划日期顺延。推演输出说明该假设。推演只保存覆盖请求和所属快照，不发布为新基线；变更上层预测是否合理、供应是否重新分配由业务判断。

## 导入操作与表结构

从现有界面下载模板或示例 Excel，按表头维护后上传。支持多工作表 `.xlsx`、`.xls`，以及每表一个 `.csv`；CSV支持带引号、引号转义、字段内换行，默认UTF-8，兼容GB18030。编码、加工地代码、供应商代码建议以文本保存，保留前导零及长编码精度。日期采用 `YYYY-MM-DD`，月份采用 `YYYY-MM`，周期均值单位天，CV用小数（0.3表示30%）。

| 表 | 必要列 / 关键字段 | 用途 |
| --- | --- | --- |
| forecast | 计划日期、编码、预测月份、预测数量；加工地代码、加工地名称、供应商代码/名称 | 版本化月度净预测和加工地集中度 |
| bom | 父项、子项、子项单位用量；id可选 | 供应依赖网络；不能循环或自环；配比小于0.01的父子项在预处理时自动过滤 |
| attributes | part_no/编码；make_dept/制造部门可留空；加工周期均值、周期变异系数、周期样本量、统计起止日期 | 产业映射、关键路径、波动风险；制造部门为空的编码在预处理阶段过滤出编码范围 |
| industry | 制造部门、是否本产业（是/否） | 跨产业分析的边界配置 |
| inventory | 创建日期、编码、可用量；子库类型可留空 | 月初库存覆盖；可用量支持负数，按减法计入 |
| adjust | 供应/使用、项目编码、外购编码；月份+数量或YYYY-MM宽表列 | 可选的原始预测预处理；供应行外购编码必填，使用行该列为空 |
| mo | 任务令号、编码、计划产出数量、计划完工日期、加工地代码 | 可选的指令供应分析；可补排产预计产出时间、实际完工日期、排产状态 |

完整预测匹配需要预测、BOM、制造属性和产业映射；加工地和周期缺失时对应分析为未知。库存及指令是增强分析，不是预测匹配的前置条件。

导入预测会替换本批涉及的**整个计划日期版本**，库存会替换涉及的**整个快照日期**；未涉及的日期保留。BOM、属性、产业映射、表2、指令按本批表整体替换。首次从演示数据导入会清除演示记录再建立业务快照。因此，同一版本或同一库存日期拆分成多个文件时，应在同一预览批次选择并一起提交，不能逐个文件提交。空工作表不执行清空。

上传后在独立进程构建，确认告警后装载。版本发生并发变化会返回409，需要基于新版本重新构建。上传和预览有效期24小时；任务记录保留7天，重启后运行中的任务明确标为中断，已完成预览可继续装载。失败和取消会释放暂存。提交期间发生连接中断应先查任务状态及 `/api/meta` 修订号，不能盲目重复提交。

新流式导入和 CLI 不设置总文件大小、累计单元格、编码数、边数硬上限，实际容量仍受内存和磁盘约束。保留单 CSV 字段16Mi字符保护、JSON请求64MiB限制和既有业务校验。Excel仍受格式及整工作簿展开的内存约束；大型输入优先使用分片CSV。具体部署边界及12万编码端到端实测见新架构说明。

## API与模型接入

| 接口 | 作用 |
| --- | --- |
| `GET /api/meta` | 快照修订号、预测版本、月份、加工地、预计算状态 |
| `POST /api/import/file?name=...` | 原始文件二进制上传，返回异步jobId |
| `POST /api/import/preview` / `commit` | 校验预计算 / 原子发布 |
| `GET /api/jobs/{id}` | 查询completed/failed及结果 |
| `GET /api/analysis` | 分页供需、角色观察和风险筛选 |
| `GET /api/nodes?code=...` | 编码详情、上层贡献、跨月供需、库存、周期 |
| `GET /api/graph` / `reports` | 有界网络、关键与风险路径 / 风险报告 |
| `POST /api/scenarios` | 创建独立推演 |
| `GET /api/openapi.json` | 完整接口目录 |
| `GET /api/ai/tools` / `POST /api/ai/invoke` | 模型工具定义 / 有界业务工具调用 |

查询支持 `version`、`month`、`mode`、`source`、`revision`、`scenario`。返回的 `trace` 固定数据修订号、预测版本、月份、口径、供应来源和情景ID。模型回答应引用这些信息，不能把null解释成零，不能把下层合计缺口分配给每个上层。

示例推演请求（月份、版本和修订号从meta获取）：

```json
{
  "baseRevision": 1,
  "version": "2026-09-10",
  "month": "2026-09",
  "mode": "cross",
  "source": "forecast",
  "type": "forecast",
  "changes": [{ "code": "A", "month": "2026-09", "operation": "percent", "value": 20 }]
}
```

现有界面和模型都调用同一个后端计算口径。模型接入已提供业务接口和工具描述，具体模型供应商、对话编排和自然语言界面尚未配置。默认仅本机访问且为管理员；对外监听需设置至少20字符的 `API_ADMIN_TOKEN`，可分别配置 `API_PLANNER_TOKEN`、`API_VIEWER_TOKEN`。管理员可导入和配置，planner可模拟，viewer只读。当前同一角色令牌共用一个服务身份；如需员工级审计和多租户隔离，应接企业身份认证后再开放给多人。

## 历史基准（分块产物改造前）

以下3万编码数据为上一轮实现的历史记录，包含旧版全量快照写入开销；当前版本性能及回归以 [离线构建与在线装载](离线构建与在线装载.md) 为准。

2026-09-10，本机Node v24.19.0，i7-12700H，约16GB内存；生成3万编码、10层、300加工地、14.85万BOM边、33万预测行、11个月数据。以下为更新后一次服务层基准，不含浏览器绘制、网络传输、Excel压缩解析及多人并发。

| 操作 | 本次耗时 |
| --- | ---: |
| 结构化数据规范化、校验、预计算 | 2.82秒 |
| 提交事务并加载已就绪快照 | 6.77秒 |
| 首次分页查询 / 缓存分页查询 | 196 / 18毫秒 |
| 单编码11个月详情 | 1.7毫秒 |
| 指定编码有界图查询 | 1.8毫秒 |
| 风险报告 | 13毫秒 |
| 单编码单月推演并保存 | 963毫秒 |
| 缓存推演详情 | 1.5毫秒 |
| 同月1000项修改推演并保存 | 768毫秒 |

批量推演在单项之后测量，缓存和垃圾回收状态不同，不能理解为1000项永远比1项更快。前一次实测导入总耗时约18秒，本次约9.6秒，磁盘缓存和内存回收会造成波动。最终进程RSS约1.0GiB，快照及索引数据库约199MiB；这些不等于HTTP双工作线程服务的总内存或峰值。生产建议从16GB内存和SSD起步，并按真实BOM边密度、预测版本数、加工地明细拆分数及并发量复测。

当前为单机SQLite、一个查询线程与一个写入/推演线程，队列有上限；不宣称已实现分布式高可用或高并发压测达标。业务增长后可增加只读计算副本、任务队列和外部身份服务，同时保留快照与API合同。

回归覆盖：三种BOM口径、独立路径枚举对照、净预测与原始调整、零与缺失、共享供应、加工地、库存、周期、指令、批量推演、缓存重开、版本与角色隔离、事务故障回滚、算法变更缓存失效、Excel/CSV实际HTTP上传到查询，以及最新图形资源与大样例接口兼容。

全部20项回归通过。另以实际CSV字节解析33万行预测（3万编码、11个月、300加工地，约12.2MiB）：解析和字段规范化约708毫秒，无错误，前导零编码完整保留；该数字不含BOM关联校验及提交事务。
